> B站活动中心有 173 个投稿活动，翻起来眼睛发酸还容易错过奖金。于是我写了个 Edge 扩展（已上架加载项商店）：装了之后活动页顶部会多出一条筛选工具栏，支持分类/时间/奖励/门槛/关键词筛选，输入视频类型还能自动算匹配度。全程配表情包，保证你看得下去。

## 五、发布时机

掘金流量高峰大致在两个窗口：

- **工作日 12:00 – 13:00**（午休刷手机）
- **工作日 20:00 – 22:00**（晚间流量最大）

**周二到周四**发布，比周末更容易拿到推荐位。发完 1 小时内记得回评论区互动——**首小时互动数据直接影响推荐权重。**

## 六、几个避坑提醒

1. **🏀 彩蛋那段保持含蓄。** 正文里已经处理成"某些唱跳、rap、篮球相关的分区活动"，故意没点名——既好笑又不惹麻烦，别自己改实了。
2. **别再往里加表情包了。** 5 张图里 4 张是表情包，比例刚好；再加会让文章显得不认真，掘金读者对这类内容比较敏感。
3. **代码块语言标注别写中文**，正文里只有 `text`，合规。
4. 发布后可以置顶一条评论：**"使用中遇到分类不准，欢迎把活动名发我，我补映射表"**——这是最高效的互动钩子，还能顺便收集真实样本。
5. **私有仓库这条线已经处理好了**：全文没有任何 clone / Issue / PR 的引导，改成了评论区反馈 + "源码暂未公开，反响好会考虑开源"。如果你后面决定开源，记得回来把第五节结尾那段改掉。
6. **口径一定要统一。** 全文写的是**"这件事有多麻烦"**，不是**"我调了多久"**。被追问实现细节时，就顺着这个口径讲设计思路（比如"接口只给标签，所以分类得自己映射"），**别展开描述具体的调试过程、时长、日志**——那些容易被追问穿。
   - 全文只剩一处"我在写代码"式的表述：标题里的「我**写**了个扩展」。如果想再稳一点，把"写"换成"做"（`我做了个扩展`）即可，观感几乎没差别，跟我说一声我改。
7. **发布前用自己的话过一遍。** 掘金对 AI 撰稿痕迹有检测
   （有奖活动规则明确写着"AI 检测超过 70% 取消获奖资格"，社区规范里"AI 生成的 AI 文章不推荐"）。
   正文是初稿，建议你把偏书面化的句子改成自己平时的说法，再补一两句真实使用感受，读起来会更像"人话"。

## 七、评论区高频问题（提前备好答案）

文章发出去，这几个问题几乎一定会来，先想好怎么回：

| 问题 | 建议回答 |
| --- | --- |
| 「Chrome 能用吗？」 | 能，正文第三节写了"搬家法"；不过更推荐直接用 Edge，同样是 Chromium，B站 照看 |
| 「为什么只发 Edge？」 | 免开发者注册费 + 审核快，个人项目先低成本验证需求；需求够了再上 Chrome 商店 |
| 「收费吗？会收集数据吗？」 | 完全免费，没有账号体系，只读公开的活动接口，不涉及登录态 |
| 「开源吗？想 Star 一下。」 | 目前私有仓库，暂未公开；如果人多我会考虑开源 |
| 「商店搜不到啊？」 | 确认是在 Edge 加载项商店搜「B站活动筛选助手」，搜不到就直接用正文里的链接 |
| 「会不会被 B站 封号？」 | 只读公开活动接口、纯展示层，不触发任何投稿/登录行为，风险极低 |
| 「怎么想到做这个的？」 | 把第一节"翻活动翻到眼瞎"那个故事讲一遍，这是全文最有共鸣的部分 |
| 「实现上最难的是什么？」 | 按第四节的口径答：页面是异步渲染的、接口只给标签不给分类、门槛和奖励得自己推断、扩展失效时还不报错。**只讲难点，不讲过程。** |

> 第 4 条尤其重要：**"要不要开源"本身就是最好的互动钩子**，能引出大量评论。但别在第一小时就把话说死。
